# E2EE over the real medium: 1:1, and a three-server group

Run 2026-09-06, three `neutrino-lan` nodes (fork at `d21ecd6` via the medium's
pin) on the iroh medium — mDNS discovery, federation on the CoAP sidecar over
QUIC, nothing seeded. The same client stack the PWA uses
(`MatrixSessionManager` + `WasmCryptoBackend`).

| contract                                                                                                                                                                                         | result      |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------- |
| encrypt on A, decrypt on B, key over the iroh link (`two-nodes.e2e.test.ts`)                                                                                                                     | pass, 5.7 s |
| three-server group: one sender's key share fanned to two homeservers, both decrypt, ciphertext-only on the sender's wire, reply from the third decrypts on both others (`mesh-e2ee.e2e.test.ts`) | pass        |

Both suites now run in CI: on three plain-HTTP nodes in the existing
live-Neutrino job (crypto and fan-out logic), and on three `neutrino-lan`
nodes in the new "E2EE over the iroh medium" job (the datagram framing and
EDU carriage a phone actually depends on).

What this does **not** cover — the seam. A phone cannot run E2EE with a
Spindle user: key shares are to-device EDUs, origin→destination only, and
phones never peer with the Spindle. See `docs/forks.md` for the full shape of
that gap.
